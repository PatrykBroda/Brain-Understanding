# **Athlete Model**

## **Core Idea**

The Athlete Model is Synochi’s evolving representation of the athlete.

It should not function as a static profile or collection of facts.

Its purpose is to maintain a **living, confidence-weighted model of how the athlete tends to perform, respond, adapt, decide, recover, learn, and change over time**.

The Athlete Model should help Synochi answer:

- What kind of athlete is this?
- What is currently affecting them?
- What patterns are stable?
- What patterns are temporary?
- What constraints repeatedly limit performance?
- What environments bring out their best or worst performance?
- What interventions tend to work for them?
- What is changing over time?
- What does Synochi still not understand?

The Athlete Model should become more useful as evidence accumulates, but it should remain permanently revisable.

## **Model Layers**

The Athlete Model can contain several interacting layers.

### **Stable Characteristics**

Relatively persistent patterns such as:

- preferred learning style,
- behavioural tendencies,
- recurring strengths,
- common decision patterns,
- technical preferences,
- motivational drivers,
- response to pressure,
- response to coaching,
- identity-linked behaviours.

These should require substantial evidence before being treated as stable.

### **Current State**

Temporary conditions that may affect behaviour or performance.

Examples:

- fatigue,
- confidence,
- stress,
- emotional disruption,
- readiness,
- motivation,
- pain,
- cognitive load,
- competitive arousal.

Current state should influence recommendations without automatically becoming part of the athlete’s stable identity.

### **Contextual Patterns**

Patterns that emerge only under particular conditions.

Examples:

Performs decisively in training but becomes hesitant in competition.

Decision quality decreases when fatigued and tactical options remain broad.

Responds well to direct challenge when confident but poorly when already overloaded.

These should be represented through [[Context-Dependent Truth]].

### **Strengths and Capabilities**

What the athlete can reliably do well.

This can include:

- physical qualities,
- technical abilities,
- tactical strengths,
- decision-making abilities,
- emotional regulation,
- learning strengths,
- competitive strengths.

Capability should be distinguished from recent performance.

A strong athlete can perform poorly in a bad state without losing the underlying capability.

### **Constraints**

Factors currently limiting progress or performance.

Constraints may be:

- technical,
- tactical,
- physical,
- psychological,
- environmental,
- structural,
- recovery-related,
- knowledge-related,
- or interaction effects between several systems.

The model should distinguish temporary constraints from persistent ones.

### **Preferences**

The athlete’s preferred ways of:

- learning,
- receiving feedback,
- structuring training,
- solving problems,
- competing,
- communicating,
- making decisions.

Preferences should inform coaching but should not override evidence that another approach produces better outcomes.

### **Goals**

The model should understand both immediate and longer-term goals.

Examples:

- prepare for a competition,
- improve a technical position,
- increase training consistency,
- recover from a difficult period,
- develop a particular style,
- improve decision-making,
- build confidence.

Goals affect what information and interventions are currently relevant.

### **Intervention History**

The Athlete Model should remember:

- what interventions were attempted,
- why they were selected,
- how the athlete responded,
- whether the intended outcome occurred,
- and how confident Synochi is that the intervention caused the change.

This should connect directly to the [[Outcome-Linked Intervention Learning Loop]].

The goal is to learn:

**What tends to work for this athlete?**

not merely:

**What advice has already been given?**

## **Evidence-Based Model Construction**

Information should not enter the Athlete Model with equal certainty.

New claims should pass through [[Evidence Weighting Model]] and [[Confidence Updating]].

A single observation may create a hypothesis.

Repeated observations may create an emerging pattern.

Repeated, contextually consistent and outcome-validated evidence may eventually create a high-confidence model component.

The progression should generally be:

**Signal → Hypothesis → Pattern → Validated Pattern → Model Integration**

## **Uncertainty**

The Athlete Model should preserve uncertainty.

Synochi should be capable of representing:

We have strong evidence for this.

This appears likely but needs more observation.

There are several plausible explanations.

We do not currently know.

Unknowns are part of the model.

They can guide future questions, observations, and experiments.

## **Contradiction**

New evidence may conflict with the existing Athlete Model.

Synochi should not silently overwrite either side.

It should use [[Competing Hypothesis Maintenance]] to determine whether:

- the original belief was wrong,
- the athlete changed,
- the behaviour is context-dependent,
- state explains the difference,
- or both patterns are valid under different conditions.

Contradiction should improve the model.

## **State Versus Identity**

The Athlete Model should avoid turning temporary states into identity claims.

For example:

The athlete is currently low in confidence.

is different from:

The athlete is an unconfident person.

Likewise:

The athlete performs poorly when severely fatigued.

does not mean:

The athlete is technically poor.

Synochi should separate **state, behaviour, capability, and identity** wherever possible.

## **Prediction**

A useful Athlete Model should improve prediction.

It should help Synochi anticipate:

- likely responses to training,
- likely breakdown points,
- likely reactions to pressure,
- which interventions may work,
- when performance may deteriorate,
- which contexts may expose a constraint.

Prediction provides an opportunity to test whether the model is actually useful.

Incorrect predictions should create learning signals.

## **Model Utility**

The Athlete Model is valuable only when it changes the quality of reasoning or action.

A mature model should materially affect:

- coaching responses,
- training recommendations,
- drill selection,
- competition preparation,
- recovery guidance,
- questions Synochi asks,
- interpretation of new observations,
- and intervention selection.

This connects to [[Model Utility]].

More stored information does not automatically mean a better Athlete Model.

The question is:

**Does knowing this athlete better produce better decisions?**

## **Continuous Updating**

The Athlete Model should continuously evolve through:

**Observation → Interpretation → Evidence Weighting → Confidence Updating → Intervention → Outcome → Model Revision**

This makes it a learning system rather than a static memory store.

## **Principle**

**The Athlete Model is not a description of who the athlete permanently is. It is Synochi’s best current model of how this athlete functions, under what conditions, with what confidence, and what appears to help them improve.**
