# **User Model**

## **Core Idea**

The User Model is Synochi’s evolving representation of the person beyond the narrow athlete-performance layer.

It should capture the patterns that meaningfully affect how the user thinks, decides, responds, learns, communicates, behaves, and changes over time.

The purpose is not to build a static personality profile.

It is to maintain a **living, revisable model of the user that improves the relevance of Synochi’s reasoning and guidance**.

The User Model should help Synochi understand:

- how the user tends to make decisions,
- what they value,
- how they respond to different forms of guidance,
- what motivates or destabilises them,
- what patterns recur across areas of life,
- what conditions improve or reduce alignment,
- what preferences are stable,
- and what still remains uncertain.

## **Scope**

The User Model can include:

- communication preferences,
- decision-making tendencies,
- motivational patterns,
- learning preferences,
- recurring behavioural patterns,
- values,
- priorities,
- identity-linked preferences,
- response to challenge,
- response to uncertainty,
- preferred level of structure,
- sensitivity to overload,
- recurring environmental influences,
- and patterns that appear across multiple domains.

It should not store information simply because it exists.

Information belongs in the User Model when it can meaningfully improve future interpretation or guidance.

## **Stable Patterns**

Some patterns may become relatively stable over time.

Examples:

- prefers direct guidance,
- responds well to clear structure,
- tends to act quickly once a decision feels aligned,
- values autonomy,
- learns well through practical examples,
- dislikes unnecessary complexity.

These should only become high-confidence User Model components when supported by repeated evidence.

## **Current State**

Temporary states should remain separate from stable user characteristics.

Examples include:

- frustration,
- excitement,
- stress,
- emotional disruption,
- low motivation,
- unusually high confidence,
- cognitive overload.

The User Model should recognise current state without allowing it to permanently redefine the person.

## **Values and Identity**

Values can materially affect whether advice feels usable.

Synochi should understand when decisions are strongly influenced by:

- autonomy,
- mastery,
- loyalty,
- ambition,
- stability,
- freedom,
- status,
- relationships,
- creativity,
- or identity fit.

The purpose is not to label the user.

It is to recognise when a recommendation may technically work but conflict with what the user actually values.

## **Decision Patterns**

The User Model should gradually learn how the user tends to make decisions.

This may include:

- whether they prefer fast or deliberate decisions,
- whether they rely heavily on intuition,
- how much evidence they require,
- what creates hesitation,
- whether external pressure helps or hurts,
- and what conditions produce decisive action.

These patterns can improve how Synochi frames options.

## **Communication Preferences**

Synochi should adapt to how the user best receives information.

Examples include:

- concise versus detailed,
- direct versus exploratory,
- structured versus conversational,
- challenge versus reassurance,
- options versus a clear recommendation.

The goal is not cosmetic personalisation.

Communication style should improve understanding and action.

## **Cross-Domain Patterns**

Some patterns may appear across sport, work, relationships, decision-making, and other areas.

These can be especially valuable.

For example:

Performance improves when structure is clear and autonomy remains intact.

If the same pattern appears repeatedly across different domains, confidence in the broader User Model can increase.

However, Synochi should avoid assuming that a pattern generalises until evidence supports it.

## **Evidence and Confidence**

User Model beliefs should be weighted according to evidence.

A single statement may create a tentative belief.

Repeated behaviour, repeated self-report, and validated outcomes should increase confidence.

The User Model should remain capable of saying:

- high confidence,
- emerging pattern,
- uncertain,
- or contradicted.

This should connect to [[Evidence Weighting Model]] and [[Confidence Updating]].

## **Relationship to the Athlete Model**

The [[Athlete Model]] is a specialised performance model.

The User Model is broader.

Some information may influence both.

For example:

User performs better when choices are narrowed under pressure.

This may affect both general decision-making and athletic performance.

Synochi should allow the two models to inform each other without collapsing them into the same thing.

## **Relevance**

The User Model should not be injected into every response.

Only relevant parts should be activated through the [[Context Engine]].

The question should always be:

Does this known pattern materially improve the current decision or response?

If not, it should remain in the background.

## **Model Evolution**

The User Model should change as the user changes.

Past behaviour should inform the model, but not imprison the user inside an outdated version of themselves.

New evidence can:

- strengthen a pattern,
- weaken it,
- make it context-specific,
- or replace it entirely.

The model should represent the best current understanding, not historical certainty.

## **Principle**

**The User Model is Synochi’s best current representation of how this person tends to function, what matters to them, and what patterns meaningfully improve future guidance.**

It should remain useful, selective, confidence-weighted, and permanently revisable.
