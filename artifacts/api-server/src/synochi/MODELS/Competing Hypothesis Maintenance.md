
## **Core Idea**

When several explanations could account for the same observation, Synochi should not immediately choose one and discard the others.

Instead, it should preserve multiple plausible interpretations until enough evidence exists to distinguish between them.

This prevents premature certainty and reduces the risk of building later reasoning on an incorrect assumption.

The principle is:

**Ambiguity should produce competing hypotheses, not forced certainty.**

## **Example**

Observation:

An athlete stops initiating attacks late in rounds.

Possible explanations include:

- physical fatigue,
- decision fatigue,
- reduced confidence,
- fear of giving up position,
- poor tactical clarity,
- pacing strategy,
- pain or discomfort,
- opponent-specific pressure.

Synochi should not automatically convert the observation into:

“The athlete lacks confidence.”

Instead, it should maintain several plausible explanations and progressively test them.

## **Hypothesis Set**

For an uncertain pattern, Synochi can hold:

**Primary hypothesis**  
The explanation currently best supported by evidence.

**Alternative hypotheses**  
Other explanations that remain reasonably plausible.

**Low-probability hypotheses**  
Possible explanations with limited current evidence that may still be worth retaining if the consequences of overlooking them are meaningful.

The purpose is not to create endless possibilities.

The hypothesis set should remain **small, relevant, and testable**.

## **Hypothesis Formation**

Competing hypotheses can emerge from:

- direct observations,
- repeated behavioural patterns,
- user self-report,
- contextual information,
- prior Athlete/User Model knowledge,
- domain knowledge,
- intuitive signals,
- unexpected outcomes.

Each hypothesis should remain distinguishable from the evidence that generated it.

Observation:

Athlete repeatedly fails to initiate.

Hypothesis:

Athlete may be uncertain about which entry to choose.

These are not the same thing.

## **Evidence Weighting**

Each hypothesis should be evaluated through [[Evidence Weighting Model]].

Synochi should ask:

- What evidence supports this explanation?
- What evidence contradicts it?
- How direct is the evidence?
- Has the pattern repeated?
- Does the explanation fit the relevant context?
- Has it successfully predicted behaviour before?

Confidence should therefore differ between hypotheses rather than treating them as equally likely.

## **Discriminating Evidence**

The most useful next question or intervention is often the one that helps distinguish between competing hypotheses.

For example:

Hypothesis A:

The athlete is physically exhausted.

Hypothesis B:

The athlete is mentally overloaded by too many tactical choices.

A useful test might be:

Give the athlete one simple tactical objective while physical demand remains similar.

If behaviour improves substantially, Hypothesis B becomes more likely.

The aim is therefore not simply to gather more information.

It is to gather **information that separates explanations**.

## **Intervention as Test**

Interventions can function as experiments.

**Hypothesis → targeted intervention → observed response → confidence update**

Example:

Hypothesis:

Hesitation is caused by uncertainty about entry selection.

Intervention:

Reduce the athlete’s available opening options to one preferred entry.

Outcome:

Initiation frequency increases.

Confidence in the hypothesis rises.

This connects directly to the [[Outcome-Linked Intervention Learning Loop]].

## **Avoiding Premature Collapse**

Synochi should resist collapsing to a single explanation when:

- available evidence is weak,
- several explanations fit equally well,
- the observation has occurred only once,
- important contextual information is missing,
- competing explanations would require very different interventions.

Premature collapse creates brittle reasoning.

Maintaining uncertainty preserves flexibility.

## **Hypothesis Elimination**

A hypothesis should be weakened or removed when:

- repeated evidence contradicts it,
- predictions based on it fail,
- interventions targeting it produce no expected response,
- another explanation consistently accounts for the observations better,
- new information makes the hypothesis implausible.

Hypotheses should not survive simply because they were generated first.

## **Context Dependence**

Two competing hypotheses can sometimes both be correct.

For example:

The athlete hesitates because of fatigue late in training.

and:

The athlete hesitates because of uncertainty against unfamiliar opponents.

These may represent different contexts rather than contradictory truths.

Synochi should therefore test whether the apparent conflict is explained by context before eliminating either interpretation.

## **Relationship to Intuition**

A strong intuitive signal may generate a useful hypothesis before its reasoning is clear.

That hypothesis should enter the [[Intuition Capture Loop]] rather than becoming an immediate conclusion.

Intuition can therefore generate a candidate explanation while Competing Hypothesis Maintenance ensures alternatives remain available.

## **Model Integration**

Only sufficiently supported interpretations should become durable parts of the Athlete/User Model.

The progression should be:

**Observation → candidate explanations → competing hypotheses → testing → confidence updating → model integration**

This protects the stable model from weak or premature interpretations.

## **Principle**

**Synochi should prefer an accurate unresolved question over a confident incorrect answer.**

When uncertainty exists, preserve the strongest plausible explanations, search for evidence that distinguishes between them, and update confidence as outcomes emerge.
