
## Purpose

This node defines how Synochi should understand movement from one established combat system into another.

A mature game should not behave like a collection of isolated systems.

It should allow the athlete to transfer between game pillars as the opponent changes the exchange.

## Core Principle

When one system loses value, Synochi should ask:

“What strong system becomes available next?”

The goal is not to force continuation inside a dying sequence.

The goal is to preserve coherence by moving into another familiar system.

## Transfer Structure

Current System
→ Opponent Reaction
→ Transfer Cue
→ New System
→ Continued Initiative

## Example

Wrestling attack
→ opponent sprawls
→ front headlock established
→ Front Headlock Pillar

The original takedown did not succeed.

But the athlete successfully transferred into another strong system.

## Another Example

Passing pressure
→ opponent turns away
→ back exposure
→ Back Attack Pillar

The pass itself may no longer be the highest-value objective.

The opponent’s reaction creates a transfer.

## Transfer Types

### Reaction Transfer

The opponent’s defence exposes another system.

### Positional Transfer

The exchange naturally moves into another established position.

### Counter Transfer

The opponent’s attack creates access to one of the athlete’s preferred systems.

### Recovery Transfer

The athlete escapes or recovers directly into an offensive pillar.

### Failure Transfer

An unsuccessful attack still creates useful access to another system.

## Transfer Cue

A transfer should be triggered by meaningful information.

Possible cues include:

- Opponent posture change
- Back exposure
- Limb exposure
- Weight shift
- Lost connection
- Defensive frame
- Sprawl
- Turn away
- Wrestle-up
- Guard recovery
- Opponent overcommitment

Synochi should learn which cues reliably signal a transfer opportunity.

## Transfer Quality

A strong transfer should:

- Preserve initiative where possible
- Move toward an established strength
- Require minimal unnecessary reset
- Match the opponent’s reaction
- Reduce decision complexity
- Maintain positional or tactical value

## Forced Transfer

Synochi should recognise when the athlete stays inside a system after its useful branches have disappeared.

This may result in:

- Low-percentage attacks
- Energy waste
- Position loss
- Missed opportunities
- Loss of initiative

The better response may be to transfer earlier.

## Premature Transfer

Leaving too early can also be inefficient.

Synochi should avoid recommending transfer when:

- Strong branches remain available
- Control is still improving
- The opponent has not solved the original system
- The transfer sacrifices a clearly superior state

## Pillar Network

Synochi should progressively map relationships between the athlete’s game pillars.

Example:

Wrestling Pillar
→ Front Headlock Pillar
→ Back Attack Pillar
→ Mount System
→ Submission System

The athlete’s game should increasingly resemble a connected network rather than separate technical categories.

## Transfer Reliability

Synochi should track:

- How often the transfer opportunity appears
- Whether the athlete recognises it
- Whether the athlete executes it successfully
- Whether the new pillar remains stable
- Whether the transfer holds up under competition resistance

## Game Coherence

The strongest transfer routes should make the athlete’s game feel continuous.

Instead of:

“Technique failed, start again.”

Synochi should favour:

“System changed, continue from here.”

## Design Objective

Synochi should help create a combat game where failure of one branch does not end the athlete’s offensive structure.

The goal is continuous navigation between reliable systems.
