
## Purpose

This node defines how Synochi should identify and organise the athlete’s highest-value combat systems into a small number of core game pillars.

A game pillar is not a single technique.

It is a reliable system that repeatedly gives the athlete access to useful positions, reactions, scoring opportunities, or finishes.

## Core Principle

Synochi should help the athlete build around a small number of highly coherent systems rather than accumulating disconnected techniques.

A strong game should increasingly become:

- Easier for the athlete to navigate
- Harder for the opponent to disrupt
- More predictable in structure
- More adaptable in execution

## Game Pillar Definition

A game pillar is a combat system that:

- Appears frequently
- Connects naturally to the athlete’s strengths
- Produces multiple useful branches
- Holds up under resistance
- Transfers across opponents
- Has clear entries
- Has reliable continuations
- Can recover when the first option fails

## Example

Front Headlock System

Possible structure:

Entry
→ Front Headlock Control
→ Opponent Reaction
→ Snapdown
→ Go-Behind
→ Submission
→ Re-shot
→ Back Exposure

The pillar is not “guillotine.”

The pillar is the entire connected front-headlock decision system.

## Pillar Components

Each game pillar should contain:

### Entry Routes

How does the athlete reliably reach the system?

### Control State

What position anchors the pillar?

### Primary Threats

What actions force meaningful opponent reactions?

### Reaction Branches

What does the opponent commonly do?

### Responses

What does the athlete do against each reaction?

### Recovery Routes

What happens when the first attack fails?

### Exit Routes

How can the athlete safely leave or transition into another pillar?

## Pillar Strength

### Emerging Pillar

Promising system with repeated success but incomplete branches.

### Functional Pillar

Reliable enough to influence training and game planning.

### Core Pillar

One of the athlete’s highest-confidence competitive systems.

## Pillar Connectivity

Synochi should identify where pillars connect.

Example:

Wrestling Pillar
→ Front Headlock Pillar
→ Back Attack Pillar

or:

Guard Pillar
→ Leg Entry Pillar
→ Top Position

The strongest athlete models may contain a small number of pillars that feed into one another.

## Pillar Redundancy

Different pillars should ideally provide answers to different combat problems.

Synochi should avoid building multiple pillars that all solve the same narrow situation while leaving major phases of combat unsupported.

## Pillar Expansion

A pillar should expand when:

- New reactions repeatedly appear
- A reliable new branch develops
- Another athlete strength naturally connects
- Competition evidence validates the addition

Expansion should remain controlled.

## Pillar Pruning

A branch or entire pillar may be downgraded when:

- It rarely appears
- It no longer performs reliably
- Another system consistently outperforms it
- It creates excessive decision load
- It conflicts with the athlete’s evolving style

## Pillar Priority

Synochi should give greater development attention to pillars that have:

- High recurrence
- High consequence
- Strong athlete fit
- Strong branch reliability
- High competition relevance
- Strong connection to other systems

## Design Objective

Synochi should progressively compress the athlete’s combat knowledge into a small number of high-confidence systems.

The goal is not to know everything.

The goal is to create a game where the athlete repeatedly reaches familiar situations, recognises the opponent’s reactions, and already has reliable answers.
