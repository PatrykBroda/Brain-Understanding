
## Purpose

This node defines how Synochi should understand the cognitive burden created by too many technical choices inside a combat system.

More options do not automatically create a better game.

A strong system should reduce unnecessary decision load while preserving enough flexibility to deal with realistic opponent reactions.

## Core Principle

Synochi should prefer:

Fewer reliable decisions
→ faster recognition
→ cleaner execution

over:

Too many possible options
→ hesitation
→ slower reactions
→ inconsistent execution

## Decision Load Structure

Situation
→ Available Options
→ Cue Recognition
→ Option Selection
→ Execution

The more options an athlete must evaluate, the greater the decision burden.

## High Decision Load

Decision load becomes excessive when:

- Too many techniques are available from the same position
- Branches overlap without clear triggers
- Athlete does not know which cue activates which response
- Several options have similar value
- Athlete repeatedly hesitates
- Athlete changes decisions mid-sequence
- Technical knowledge exceeds practical reliability

## Low Decision Load

A well-structured system may contain:

- One primary objective
- Two or three common opponent reactions
- One reliable answer for each reaction
- One safe fallback

This gives the athlete clarity without making the system rigid.

## Cue-Based Simplification

Synochi should reduce decision load by linking actions to clear opponent cues.

Example:

Opponent stays low
→ attack front headlock

Opponent builds posture
→ go behind

Opponent drives forward
→ re-attack

The athlete does not need to choose between every possible technique.

They need to recognise the cue.

## Option Redundancy

Synochi should identify when multiple techniques solve the same problem.

If three options produce similar outcomes, Synochi should ask:

- Which is most reliable?
- Which best fits the athlete?
- Which has the strongest continuation?
- Which creates the lowest decision burden?

Lower-value redundant options may be deprioritised.

## Decision Compression

As evidence accumulates, Synochi should compress complex technical knowledge into simple rules.

Example:

Instead of:

“From this position you can use five different attacks.”

Prefer:

“If they turn in, do this.
If they turn away, do this.”

This creates a more usable combat system.

## Decision Load Under Pressure

Competition, fatigue, speed, and stress can reduce decision capacity.

Synochi should account for this when recommending systems.

A technically complex system that works in drilling may fail under competition pressure because decision load becomes too high.

## Athlete-Specific Decision Capacity

Different athletes may perform well with different levels of complexity.

Synochi should learn whether the athlete performs better with:

- Simple narrow systems
- Moderate branching
- High improvisational freedom

The system should adapt to the athlete rather than force one model of complexity.

## Complexity Threshold

New branches should only be added when:

- Existing branches are reliable
- A meaningful recurring problem remains unsolved
- The new branch has a clear cue
- The athlete can recognise and execute it
- The added complexity produces enough value

## Design Objective

Synochi should help the athlete build systems that are simple enough to execute under pressure and flexible enough to handle realistic resistance.

The goal is not maximum technical variety.

The goal is maximum usable intelligence.
