
## Purpose

This node defines how Synochi should understand the ways an athlete safely leaves, resets, or transfers out of a combat system when continuation is no longer high value.

A good system should not only have entries and attacks.

It should also have clean exits.

## Core Principle

Synochi should distinguish between:

- Productive continuation
- Forced continuation
- Tactical reset
- Safe disengagement
- Transfer into another game pillar

Staying in a system too long can become as inefficient as abandoning it too early.

## Exit Route Definition

An exit route is a repeatable pathway from a current system into:

- Neutral position
- Safer structure
- Another strong game pillar
- Tactical reset
- Controlled disengagement

## Exit Route Categories

### Neutral Exit

Return to a stable neutral state.

### Defensive Exit

Leave the current exchange to reduce risk.

### Transfer Exit

Move directly into another game pillar.

### Reset Exit

Break the exchange and rebuild from a preferred starting condition.

### Scoring Exit

Secure the available score or positional gain rather than forcing further attack.

## Exit Triggers

Synochi should recognise when an exit may be preferable because:

- Branch reliability drops
- Opponent has fully stabilised
- Position is becoming increasingly risky
- Athlete is losing structural control
- Energy cost is rising without useful progress
- Time or score changes the tactical objective
- Another game pillar becomes more accessible
- The current system has reached a dead end

## Example

Athlete attacks from front headlock.

Opponent successfully clears the immediate submission threat and begins regaining posture.

Possible options:

- Force another low-percentage attack
- Disengage
- Re-shot
- Go behind
- Transition into another control system

Synochi should evaluate whether continuing the original system still has positive expected value.

## Exit Quality

A strong exit should:

- Preserve position where possible
- Avoid unnecessary exposure
- Maintain initiative when possible
- Connect to another familiar state
- Reduce decision chaos
- Avoid excessive energy expenditure

## Bad Exit

An exit may be poor when the athlete:

- Gives up dominant position unnecessarily
- Disengages while strong continuation remains
- Creates a scramble that favours the opponent
- Abandons a system because of hesitation rather than tactical need
- Exits into an unfamiliar or low-value state

## Exit vs Failure

Leaving a system does not automatically mean the system failed.

A successful sequence may end with:

Entry
→ Threat
→ Opponent forced to defend
→ Positional improvement
→ Tactical exit

The athlete may have gained value even without completing the original attack.

## Pillar Transfer

High-level game architecture should allow movement between pillars.

Example:

Leg Entry System
→ opponent clears knee line
→ wrestle-up
→ Wrestling Pillar

or:

Passing System
→ opponent turns away
→ Back Attack Pillar

Synochi should identify these transfers as successful exits rather than broken sequences.

## Exit Reliability

Synochi should track whether the athlete can consistently:

- Recognise when the current system is exhausted
- Leave without conceding major advantage
- Transfer into another strong position
- Reset without unnecessary risk

## Design Objective

Synochi should understand when to stop forcing a sequence.

The goal is to create systems with reliable entries, strong internal branches, and intelligent exits.

A mature game should allow the athlete to move between systems without losing coherence.
