## [[Error Masking]]

  

Type: [[Failure Detection Node]]

  

Definition:

A condition where system optimisation conceals errors by smoothing outcomes, delaying visibility of failure until damage is systemic.

  

Core Statement:

When errors no longer hurt, learning stops.

  

Mechanism:

Error masking occurs when [[Optimisation]] or [[Assistance]] absorbs mistakes before they reach [[Perception]] or [[Responsibility]].

  

Common Masking Sources:

- [[Over-Automation]]
    
- [[Predictive Correction]]
    
- [[Excessive Scaffolding]]
    
- [[Outcome Smoothing]]
    
- [[Latency Compensation]]
    

  

Downstream Indicators:

- Reduced [[Error Awareness]]
    
- Declining [[Recovery Skill]]
    
- Confidence without calibration
    
- Surprise at failure events
    
- Inability to explain why success occurred
    

  

Radar Triggers:

- Fast success with shallow understanding
    
- Absence of friction where friction is expected
    
- Repeated correctness without authorship
    
- Delayed catastrophic failure
    

  

System Response:

- Increase [[Resistance]]
    
- Remove [[Error Absorption]]
    
- Reintroduce [[Exposure]]
    
- Force [[Post-Action Review]]
    
- Restore [[Cost of Mistake]]
    

  

Invariant:

Errors must remain felt to remain informative.

  

Failure Modes if Unchecked:

- [[Silent Skill Decay]]
    
- [[False Mastery]]
    
- [[Brittle Competence]]
    
- [[Catastrophic Surprise]]
