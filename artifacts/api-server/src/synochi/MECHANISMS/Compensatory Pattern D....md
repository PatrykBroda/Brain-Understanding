# Compensatory Pattern Detection

## Definition
Compensatory Pattern Detection identifies when the system is achieving an outcome through a workaround rather than through stable underlying control.

## Principle
Successful performance does not always mean the underlying system is functioning well.

A person can preserve output by shifting load elsewhere, increasing effort, narrowing options, or relying on a stronger subsystem to cover a weaker one.

Compensation can maintain short-term function while hiding instability.

## Function
Compensatory Pattern Detection helps Synochi distinguish:
- true adaptation from workaround
- stable capability from effortful substitution
- resilient performance from fragile performance
- progress from hidden redistribution of load

## Common Forms

### Physical Compensation
One movement, muscle group, or position absorbs demand because another cannot manage it effectively.

### Cognitive Compensation
Extra attention, effort, checking, or control is used to maintain performance that should otherwise be more automatic.

### Behavioural Compensation
A person relies on avoidance, ritual, overpreparation, or environmental control to maintain stability.

### Strategic Compensation
One strength is repeatedly used to cover an unresolved weakness.

## Operational Pattern
Outcome appears successful  
→ inspect how the outcome was achieved  
→ identify abnormal effort, substitution, or narrowing of options  
→ determine what underlying instability is being covered  
→ decide whether the compensation is adaptive or limiting  
→ restore stability before increasing complexity or load

## Relationship to Stability First Progression
Compensatory patterns matter because progression built on instability can amplify the workaround.

Before adding speed, complexity, load, or freedom, Synochi should determine whether the current level is stable without excessive compensation.

If the system can only succeed by continually borrowing capacity from elsewhere, the base is not yet stable.

## Constraint
Compensation is not always negative.

Temporary compensation can be useful when:
- protecting an injury
- adapting to a temporary constraint
- solving an unfamiliar problem
- preserving function during transition

The problem begins when the workaround becomes the default and prevents restoration of the underlying capacity.

## Core Rule
Do not mistake preserved output for stable function.
