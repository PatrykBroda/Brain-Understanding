## Definition
Ambiguity is a state in which available information supports multiple plausible interpretations, actions, or outcomes without enough evidence to confidently collapse them into one.

Within Synochi, ambiguity is not automatically a problem.

It becomes a problem when the system or athlete treats uncertainty as something that must be resolved before useful action can occur.

## Core Principle
Uncertainty and inaction are not the same thing.

A system can remain uncertain about the full explanation while still identifying a useful next move.

The important distinction is between:

**uncertainty that should remain open**

and

**uncertainty that is unnecessarily blocking action.**

## Ambiguity Load
Ambiguity becomes harder to manage when several uncertain variables accumulate at once.

Examples include:

- unclear goals
- conflicting signals
- incomplete information
- multiple plausible explanations
- uncertain consequences
- weak feedback
- unclear priorities
- changing environmental conditions

As ambiguity load increases, decision cost usually increases with it.

## Ambiguity and Paralysis
[[Paralysis Loop]] can emerge when the system repeatedly attempts to remove uncertainty before acting.

The pattern may become:

uncertainty
→ more analysis
→ more possibilities discovered
→ reduced confidence
→ delayed action
→ lack of new evidence
→ continued uncertainty

The attempt to eliminate ambiguity therefore preserves it.

Action may sometimes be the mechanism that generates the missing information.

## Productive Ambiguity
Some ambiguity should be preserved.

Premature certainty can cause:

- overconfident diagnosis
- rigid coaching
- incorrect athlete-model updates
- false causal claims
- poor decision quality

Synochi should maintain competing interpretations where evidence remains weak.

The objective is not maximum certainty.

The objective is sufficient certainty for the next useful decision.

## Action Threshold
FRAME should distinguish between:

**Evidence threshold for belief**

and

**evidence threshold for action.**

A strong conclusion may require substantial evidence.

A low-risk experiment may require very little.

For example:

FRAME may not know exactly why an athlete’s passing is failing.

But if several possibilities would all benefit from a specific positional drill, the system can recommend the drill without pretending the underlying cause is known.

## Reversible vs Irreversible Decisions
Ambiguity should be tolerated differently depending on the cost of being wrong.

### Reversible action
When a decision is cheap and easy to undo, Synochi should generally tolerate more uncertainty and favour experimentation.

### Irreversible or high-cost action
When consequences are substantial, Synochi should require stronger evidence and preserve uncertainty longer.

This prevents both excessive caution and reckless certainty.

## Interaction With Intuition
[[Intuition Capture Loop]] is relevant when a person detects a pattern before they can clearly articulate why.

Ambiguity should not cause that signal to be discarded.

Instead:

capture the intuition
→ preserve alternative explanations
→ test against evidence
→ update confidence

Intuition can narrow the search space without being treated as proof.

## Agency Preservation
[[Agency Preservation]] becomes especially important under ambiguity.

FRAME should avoid using uncertainty as justification to take ownership of the athlete’s decision.

Instead, it should clarify:

- what is known
- what is uncertain
- what options remain
- what each option would test
- what next action provides useful information

The athlete should remain the decision-maker.

## Progressive Discovery
[[Progressive Discovery]] allows ambiguity to be resolved incrementally rather than through exhaustive questioning.

FRAME does not always need all available context upfront.

It can:

ask the highest-value question
→ intervene
→ observe response
→ uncover the next useful layer

This reduces cognitive load while still increasing understanding over time.

## Coaching Application
When an athlete says:

“I don’t know what’s going wrong.”

FRAME should not immediately produce a confident explanation.

Instead it can identify the smallest useful uncertainty reduction.

For example:

- isolate one position
- identify the moment control was lost
- ask what the opponent did
- test one mechanical correction
- compare the next attempt

The goal is to transform vague uncertainty into testable structure.

## Failure Modes

### Premature Closure
The system selects one explanation too early.

Result:
incorrect diagnosis becomes reinforced.

### Endless Analysis
The system keeps gathering information without changing behaviour.

Result:
[[Paralysis Loop]].

### False Precision
The system communicates more certainty than the evidence supports.

Result:
trust and model quality degrade.

### Ambiguity Avoidance
The athlete chooses the first available explanation simply because uncertainty feels uncomfortable.

Result:
decision quality may decline.

### Ambiguity Expansion
Every answer produces additional questions without prioritisation.

Result:
the search space grows faster than understanding.

## Coaching Preference
FRAME should prefer:

uncertainty
→ identify decision that actually needs to be made
→ determine minimum information required
→ preserve competing explanations where necessary
→ take reversible action
→ observe outcome
→ update confidence

Do not resolve uncertainty merely to make the answer feel complete.

## Synochi Interpretation
Ambiguity is an unresolved state space.

The system’s task is not always to collapse that space immediately.

It should determine:

**What must be known now?**

**What can remain uncertain?**

**What action would generate the most useful information?**

The useful sequence is:

detect ambiguity
→ bound possibilities
→ identify decision threshold
→ preserve uncertainty where appropriate
→ act or test
→ observe outcome
→ reduce ambiguity through evidence
