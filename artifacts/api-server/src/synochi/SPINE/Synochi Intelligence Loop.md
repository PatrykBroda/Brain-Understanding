## **Core Idea**

Synochi operates as a continuous adaptive intelligence loop.

It does not simply retrieve information and produce an answer.

It receives input, interprets what the input means, updates its understanding of the person or athlete, selects the context that matters, chooses an intervention or decision, observes what happens next, and uses that outcome to improve future behaviour.

The loop is:

**Input → Interpret → Model Update → Context Selection → Decision / Intervention → Outcome Observation → Learning**

This is the core operating cycle through which Synochi becomes more useful over time.

## **1. Input**

Synochi receives a signal.

Input may come from:

- conversation,
- self-report,
- training sessions,
- uploaded video,
- competition,
- recovery data,
- wearable data,
- behavioural patterns,
- check-ins,
- or previous intervention outcomes.

Input is not yet meaning.

It is raw or semi-structured evidence entering the system.

## **2. Interpret**

Synochi determines what the input may represent.

Interpretation can involve:

- identifying patterns,
- recognising state,
- detecting constraint,
- comparing the input with previous behaviour,
- distinguishing signal from noise,
- and considering multiple explanations.

Interpretation should remain uncertainty-aware.

The system should distinguish:

**what was observed**

from:

**what is inferred.**

## **3. Model Update**

Useful evidence can modify Synochi’s representation of the user or athlete.

This may update:

- [[Athlete Model]],
- [[User Model]],
- current state,
- confidence in an existing pattern,
- intervention history,
- preferences,
- strengths,
- constraints,
- or unresolved hypotheses.

Not every input should create a durable model update.

The strength of the update should reflect the quality and relevance of the evidence.

## **4. Context Selection**

Synochi then determines which information matters for the current problem.

The system may know a large amount, but only part of that knowledge should influence any one decision.

[[Context Engine]] selects the relevant combination of:

- current state,
- goals,
- recent events,
- stable patterns,
- active constraints,
- specialist knowledge,
- and prior outcomes.

This converts accumulated knowledge into active context.

## **5. Decision / Intervention**

Synochi selects an action.

This may be:

- a coaching recommendation,
- a drill,
- a question,
- a technical adjustment,
- a recovery intervention,
- a reframing,
- a competition strategy,
- a behavioural suggestion,
- or a decision to gather more information before acting.

The intervention should emerge from:

**current context + current model + current objective**

rather than generic knowledge alone.

## **6. Outcome Observation**

After action, Synochi observes what happens.

The response may include:

- improvement,
- deterioration,
- no meaningful change,
- unexpected behaviour,
- partial success,
- or a context-dependent effect.

The outcome becomes new evidence.

This closes the distance between recommendation and reality.

## **7. Learning**

Synochi uses the outcome to update future behaviour.

It asks:

- Was the interpretation correct?
- Did the intervention change the intended variable?
- Was the response expected?
- Did confidence increase or decrease?
- Should the same intervention become more or less likely next time?
- Did the model miss something important?

Learning then changes future interpretation, selection, and intervention policy.

The loop begins again.

## **Recursive Operation**

The loop is recursive.

Every outcome becomes a new input.

Therefore:

**Input**

↓

**Interpret**

↓

**Model Update**

↓

**Context Selection**

↓

**Decision / Intervention**

↓

**Outcome Observation**

↓

**Learning**

↓

**New Input**

Synochi is not moving toward a final static model.

It is continuously updating its best current representation of the person and the situation.

## **Specialist Intelligence**

Specialist layers can enter the loop during interpretation and decision.

For example:

Combat Intelligence may help interpret a technical failure.

Recovery Intelligence may help interpret fatigue.

Competition Intelligence may alter context during event preparation.

The specialist layer changes the meaning of the input, but the broader Synochi loop remains the same.

## **Why This Matters**

Without this loop, FRAME risks becoming:

**Input → Answer**

That creates responsive AI.

With the full loop:

**Input → Understanding → Personalisation → Intervention → Outcome → Learning**

the system begins to become adaptive.

The difference is not simply memory.

It is closed-loop learning.

## **Synochi Interpretation**

Synochi is best understood as an **adaptive inference-and-action architecture**.

Its intelligence does not exist only in what it knows.

It exists in how it:

- interprets signals,
- changes its internal models,
- selects relevant context,
- acts under uncertainty,
- and learns from consequence.

Knowledge provides possible answers.

The loop determines which answer should matter now and whether it should be trusted again later.

## **Principle**

**Synochi should not merely remember the past or respond to the present. It should use both to improve how it acts in the future.**

The operating cycle is:

**Input → Interpret → Model Update → Context Selection → Decision / Intervention → Outcome Observation → Learning**
